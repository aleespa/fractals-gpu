# WinUI 3 Fractal Explorer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Node/browser explorer with a standalone C# WinUI 3 app that renders in-process through a native CUDA DLL, keep the CLI working on the same DLL, then delete the web version.

**Architecture:** `FractalCore.dll` (CUDA 12.9, flat `extern "C"` API) holds the unchanged kernels and the 32-row band launcher. `CppFractals.exe` (CLI) and the C# app both call it. Pure C# logic (palette, view math, export math, CLI command text, P/Invoke wrapper) lives in a `FractalExplorer.Core` class library with xUnit tests. The WinUI 3 app (`FractalExplorer`) is a thin UI over it.

**Tech Stack:** MSVC v143 (VS 2022 17.14), CUDA 12.9 build customization, `stb_image_write`, .NET 8, Windows App SDK (WinUI 3, unpackaged, self-contained), xUnit.

**Spec:** `docs/superpowers/specs/2026-11-20-winui3-app-design.md`

## Global Constraints

- Branch `winui3-app`. Pixel-identity baseline is commit `59eca05`'s CLI.
- VS 2022 / toolset v143, CUDA 12.9, `CodeGeneration` stays `compute_75,sm_75`. x64 only.
- Kernel math in `Fractal.cu` stays identical. Keep 32-row band launches with 16×16 blocks.
- CLI argument contract unchanged: `<type> <w> <h> <iter> <x> <y> <zoom> <cx> <cy> <out.png> [--ss N] [t hex ...]`, ss clamped 1..8, built-in 5-stop palette when none given.
- App: `WindowsPackageType=None`, `WindowsAppSDKSelfContained=true`, `SelfContained=true`, `RuntimeIdentifier=win-x64`, TFM `net8.0-windows10.0.19041.0`.
- No network, no server, no temp files for interactive frames.
- Never touch or commit `output_*.png` in the repo root.
- Full build: `msbuild CppFractals.sln /restore /m /p:Configuration=Release /p:Platform=x64` (VS 2022 Developer PowerShell).
- Tests: `dotnet test tests\FractalExplorer.Tests\FractalExplorer.Tests.csproj -c Release -p:Platform=x64` after the full build.
- All number↔text conversions in C# use `CultureInfo.InvariantCulture`, except the on-screen zoom readout.

## Review Focus

1. **Non-English Windows locale** (e.g. Spanish, decimal comma): the copied CLI command and the palette `t` values must still use `.` decimals, or the CLI misparses them. Test: `CliCommandTests.Build_UsesInvariantCulture_UnderSpanishCulture` (Task 3).
2. **Save path with non-ASCII characters or spaces** (e.g. `C:\Users\Alejandro\Imágenes\…`): export must still write the file. Test: `NativeRendererTests.WritePng_NonAsciiPath` (Task 4), via `STBIW_WINDOWS_UTF8`.
3. **Image sizes that aren't multiples of 16 / 32** (odd window sizes, custom export like 1001×333): no garbage rows, matches baseline. Covered by baseline case `odd` (Task 0/1) and `Render_MatchesCli_OddSize` (Task 4).
4. **No CUDA device / DLL missing / out-of-GPU-memory export** (e.g. 16384×16384 at 16×): the app shows an error message and stays usable instead of crashing. Test: `NativeRendererTests.Render_InvalidSize_Throws` (Task 4) and manual check in Task 7 step for a failed export.
5. **Rapid interaction while a render is in flight** (fast wheel spins, dragging during an export): superseded renders are cancelled, the newest view always wins, and the export is not corrupted. Test: `NativeRendererTests.Render_PreCancelled_ReturnsCancelled` (Task 4) + manual check in Task 5.

```c
#pragma once
#include <stdint.h>
#ifdef FRACTALCORE_EXPORTS
#define FC_API __declspec(dllexport)
#else
#define FC_API __declspec(dllimport)
#endif
#ifdef __cplusplus
extern "C" {
#endif

enum { FC_OK = 0, FC_CANCELLED = 1, FC_ERR_INVALID = 2, FC_ERR_CUDA = 3, FC_ERR_IO = 4 };
enum { FC_FORMAT_RGB8 = 0, FC_FORMAT_BGRA8 = 1 };   /* BGRA8: alpha = 255 */

typedef struct FcParams {
    int32_t type;            /* 0 Mandelbrot, 1 Julia */
    int32_t width, height;   /* 1..16384 */
    int32_t maxIterations;   /* >= 1 */
    double  xCenter, yCenter;
    double  zoom;            /* half-width in the complex plane; half-height = zoom / (w/h) */
    double  cx, cy;          /* Julia constant */
    int32_t ss;              /* clamped to 1..8 */
    int32_t paletteSize;     /* 0 => built-in 5-stop default palette */
    const float* palT;       /* paletteSize entries, sorted ascending */
    const float* palRGB;     /* paletteSize*3 entries, 0..1 */
} FcParams;

/* out: width*height*3 (RGB8) or *4 (BGRA8) bytes, top row first.
   cancelFlag may be NULL; non-zero => stop after the current band, return FC_CANCELLED.
   Calls are serialized internally (one GPU job at a time). */
FC_API int32_t fc_render(const FcParams* p, uint8_t* out, int32_t format,
                         const volatile int32_t* cancelFlag);
/* RGB8 buffer -> PNG via stb_image_write. pathUtf8 is UTF-8. */
FC_API int32_t fc_write_png(const char* pathUtf8, int32_t width, int32_t height,
                            const uint8_t* rgb);
/* Message for the last non-OK result on this thread ("" if none). */
FC_API const char* fc_last_error(void);

#ifdef __cplusplus
}
#endif
```
- In C# the struct layout is sequential with natural alignment. The `int32 ss; int32 paletteSize;` pair precedes the pointers, so there's no hidden padding before `palT` at offset 64. Task 4 relies on this.
